# 10｜从“跑通”到可信研究

一个逐渐下降的 loss，不等于更强的模型。一段正确回答，也不等于稳健泛化。
本项目把测试、smoke、任务质量、系统性能分成四类证据。

## 四道门

| 层级 | 证明什么 | 不能证明什么 |
|---|---|---|
| 数值单测 | 公式、梯度、mask、缓存与 oracle 一致 | 真实语料能训练稳定 |
| 全流程 smoke | 各阶段输入输出与 checkpoint 连通 | 通用聊天或推理能力 |
| 持出任务评测 | 特定分布、协议下的表现 | 任意领域的能力 |
| 性能测量 | 特定软硬件与负载的延迟/内存 | 所有笔记本或生产集群表现 |

## 最小实验报告模板

```text
问题：要检验哪一个可证伪假设？
对照：唯一改变的变量是什么？
数据：来源、许可、版本/hash、去重、切分、污染检查。
预算：参数/激活参数、训练 tokens、生成 tokens、种子、时间、设备。
目标：完整公式、KL 方向、mask、loss reduction、采样温度。
结果：每个种子、均值/范围、失败样例、截断率、零方差组比例。
判定：支持/不支持假设；还有哪些替代解释？
复现：Git commit、环境、命令、checkpoint 与日志路径。
```

## 建议的四个毕业实验

**A｜Attention 消融。** 相同 tokenizer、数据、dim、层数，比较 dense GQA 与滑窗/混合。
先跑 dense oracle、cache、因果性测试，再比较 loss 与时间/显存。
不同 attention pattern 本身改变函数，不要求模型质量完全一致。

**B｜MoE 容量与计算。** 固定每 token 激活 FFN 预算，改变总专家数。报告总参数与激活参数，
路由频率、平衡项、task loss；不能只展示参数增长后的分数而不讨论预算。

**C｜SFT → GRPO。** 先在独立算术题上建立非零基线，确认采样能产生正确与错误回答，
再做 GRPO。对照组用相同计算预算继续 SFT；报告多个种子、格式通过率、最终正确率、长度。
如果全零组很多，记录失败；不要在验证器里偷偷给随机答案部分分来“制造改进”。

**D｜离线与在线蒸馏。** 固定教师、题目、student 初始化和 token 总预算，对比教师轨迹
SFT 与学生轨迹 KL。教师要先独立评估；更密集的信号也可能学会更多教师偏差。

## CoT 评测不能只检查答案

最终准确率、步骤有效性、格式合规、长度、随机种子稳定性可以分开评测。
pass@k 与 pass@1 含义不同，增加采样次数会消耗更多测试时计算。报告 k、温度与预算。
本仓库 `evaluation.py` 的关键词检查只是一种 smoke 诊断，容易被重复题目或关键词刷分，
不是推理 benchmark。算术 verifier 更严格，但仍只检查有限任务的最终整数。

## 代码阅读验收题

1. 为什么 old logp 不能每个 PPO epoch 重新写入？reference 又为什么不能每个 rollout 刷新？
2. 为什么全零 reward 的 MoE-GRPO 仍可能改变参数？怎样分离任务梯度与 router 梯度？
3. 为什么 MLA 权重吸收不能直接把所有 RoPE 混入一个固定矩阵？
4. 为什么 LoRA 注入时 A 第一轮没有梯度不一定是 bug？
5. 为什么不同 rank 的 token 数不同会破坏“平均梯度就是大 batch 梯度”的直觉？
6. 一个网页能流式回答，离带 SLO 的 serving 平台还差哪些组件？

能在代码里定位答案、设计反例测试、解释未覆盖的边界，才说明掌握了工作方法。
这比承诺“读完与顶尖实验室只差算力”更接近真实研究训练。
